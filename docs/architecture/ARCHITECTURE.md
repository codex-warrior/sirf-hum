# Architecture

Status: **Foundation implemented (Prompt 01).**

## System overview

```text
┌──────────────── Flutter client (Android · iOS · Web, one codebase) ────────────────┐
│ presentation → application (Riverpod) → domain ← data                               │
│                                              │                                      │
│        lib/security (plaintext ⇄ EncryptedEnvelope; keys never leave device)        │
│                                              │                                      │
│        lib/infrastructure (Firebase SDKs, LiveKit SDK)   lib/platform (device APIs) │
└──────────────────────────────────────────────┼──────────────────────────────────────┘
                     TLS (transport only)      │
┌──────────────────────────────── Firebase ────┴──────────────────────────────────────┐
│ Auth · Firestore (metadata + ciphertext) · Storage (ciphertext) · Cloud Functions   │
│ (trusted logic, LiveKit token minting, notification fan-out) · FCM · App Check      │
└─────────────────────────────────────────────────────────────────────────────────────┘
                                  LiveKit (realtime media SFU)
```

## Client module layout (`lib/`)

| Path | Responsibility | May depend on |
| --- | --- | --- |
| `main.dart` | Composition root: load config, bootstrap Firebase, `runApp` | everything |
| `app/` | App widget, router, navigation shell, root providers, `AppConfig` | design_system, core, infrastructure (bootstrap only) |
| `core/` | Cross-cutting, dependency-free utilities: environment enum, logging | Dart/Flutter SDK only |
| `design_system/` | Tokens, theme, (later) shared components | Flutter only |
| `features/<area>/` | Product areas: `home`, `together`, `moments`, `future`, `us` | core, design_system, security, infrastructure (data layer only) |
| `security/` | Cryptography boundary, key management (future) | core |
| `infrastructure/` | Firebase, LiveKit integrations | core, security (envelope types) |
| `platform/` | Device capability wrappers (permissions, camera, secure storage…) | core |

Rules:

- Features don't import each other's `presentation/` or `data/`.
- Firebase SDK imports appear only in `infrastructure/` and feature `data/`.
- Private relationship content crosses into `infrastructure/` only as
  `EncryptedEnvelope` (`lib/security/crypto/encrypted_envelope.dart`).
- Layers within a feature are created when needed, not up front
  (`lib/features/README.md`).

## State management and navigation

- **Riverpod** (`flutter_riverpod`, no code generation for now). Root
  providers in `lib/app/app_providers.dart` are overridden in `main.dart`
  with values computed before `runApp` (config, Firebase status).
- **go_router** with a `StatefulShellRoute` — each area keeps its own
  navigation stack; every area is URL-addressable for notification deep
  links and the web. Auth/pairing redirects arrive in the identity phase.

## Trust boundaries (summary)

1. **Device ↔ network:** plaintext private content never leaves the
   security layer. Servers receive ciphertext + minimal metadata.
2. **Client ↔ Firebase:** clients are untrusted. Authorization lives in
   Security Rules and Cloud Functions; client checks are UX only.
3. **Firebase ↔ Cloud Functions:** Functions are trusted for *metadata and
   policy*, not for private content (they never hold content keys).
4. **App ↔ LiveKit:** access only via short-lived tokens minted by Cloud
   Functions after membership checks.
5. **App ↔ OS services:** notifications, logs, crash reports and backups
   are outside the trust boundary for private content.

Full analysis: [../security/THREAT-MODEL.md](../security/THREAT-MODEL.md).

## Environments

Full model, isolation layers, App Check, Crashlytics and CI secrets:
[ENVIRONMENTS.md](ENVIRONMENTS.md). Developer workflow:
[DEVELOPMENT-ENVIRONMENT.md](DEVELOPMENT-ENVIRONMENT.md).

| Environment | Firebase project | App ID (Android & iOS) | Client config |
| --- | --- | --- | --- |
| `development` | `sirf-hum-dev` | `com.sirfhum.app.dev` | `config/env/development.json` |
| `staging` | `sirf-hum-staging` | `com.sirfhum.app.staging` | `config/env/staging.json` |
| `production` | `sirf-hum-prod` | `com.sirfhum.app` | `config/env/production.json` (CI-only) |

- Selection: `--flavor <env>` (mobile) **and**
  `--dart-define-from-file=config/env/<env>.json`. Without a config file the
  build is `development` with Firebase not configured.
- `lib/app/environment_guard.dart` aborts startup when flavor, `SH_ENV` and
  Firebase project disagree.
- Only `config/env/*.example.json` is committed. Real files are generated by
  `tool/generate_env_config.mjs`. Client values are identifiers, not secrets;
  secrets live in Cloud Functions Secret Manager / GitHub Environment secrets.
- Production config is injected by CI from the `production` environment's
  secrets, never stored on developer machines by default.

## Code quality

- **Formatting:** `dart format` (CI fails on diff).
- **Analysis:** `flutter analyze` with `strict-casts`, `strict-inference`,
  `strict-raw-types`, `flutter_lints` plus extra rules in
  `analysis_options.yaml` (package imports, trailing commas, const, no
  `print`, unawaited futures as errors, sorted directives).
- **Naming:** files `snake_case.dart`; types `UpperCamelCase`; one public
  widget per file where practical; tests mirror `lib/` paths with `_test.dart`.
- **Imports:** always `package:sirf_hum/...`; UI code imports the design
  system barrel only.
- **Comments:** explain *why*, not *what*. Doc comments on public APIs that
  encode a rule (security, privacy, accessibility).
- **Logging:** only `AppLogger` (`lib/core/logging/`); typed fields, raw
  strings redacted, error types only. Never private content, keys or tokens.
- **Functions (TypeScript):** `strict` mode; `npm run check` = typecheck +
  ESLint (type-checked, defect-oriented rules) + build + unit tests.

## Commands

```sh
tool/verify.sh          # format check, analyze, unit + widget tests
tool/verify.sh --all    # + Functions check, Security Rules tests, web + Android builds
tool/deploy.sh <env>    # environment-explicit deploy (see ENVIRONMENTS.md)
```

CI: `.github/workflows/ci.yml` validates (Flutter, web per environment,
Android dev/staging debug + production release, iOS all schemes on macOS,
Functions, Security Rules, gitleaks history scan) with no secrets.
`.github/workflows/deploy.yml` deploys manually per environment.
